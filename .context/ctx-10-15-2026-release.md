# Release, distribution and updates

How Agent Sounds Bar is versioned, signed, published and updated. Added 10-15-2026 for the first public release (v1.0.0).

## Where things live
- Public repo: `github.com/ealexisaraujo/agent-sounds-bar` (personal account, MIT).
- Homebrew tap: `github.com/ealexisaraujo/homebrew-tap`, cask `Casks/agent-sounds-bar.rb`. Install: `brew install --cask ealexisaraujo/tap/agent-sounds-bar`.
- Cask template: `packaging/homebrew/agent-sounds-bar.rb` (placeholders `__VERSION__`, `__SHA256__`). The tap copy is generated by the release script; edit the template, not the tap.
- Version: `VERSION` file. `build.sh` writes it to `CFBundleShortVersionString`; `CFBundleVersion` is `git rev-list --count HEAD`.
- Notes: the version's section in `CHANGELOG.md` (`## [x.y.z] - date`) becomes the GitHub release body.
- Bundle id: `com.alexisaraujo.AgentSoundsBar` (was `local.agent-sounds-bar` before 1.0.0, so UserDefaults and the login item start fresh).

## Release flow (`scripts/release.sh`)
1. Bump `VERSION`, add the CHANGELOG section, commit.
2. `scripts/release.sh build`: requires a clean tree; runs both test suites; `UNIVERSAL=1 SIGN_IDENTITY=... ./build.sh` (arm64 + x86_64, hardened runtime, secure timestamp); checks the team id; zips with `ditto`; `notarytool submit --wait`; staples; re-zips so the ticket ships inside; `spctl --assess`; writes `dist/AgentSoundsBar-<v>.zip` and `.sha256`. Publishes nothing.
3. `scripts/release.sh publish`: checks the zip still matches its checksum, tags `v<version>`, pushes the tag, `gh release create` (with `--prerelease` when the version contains `-`), then for stable versions renders the cask with the new version and sha256 and pushes it to the tap.

Signing identity: `Developer ID Application: Enrique Alexis Araujo (PN2FR53G7Y)` in the login keychain. Notarization uses the keychain profile `agent-sounds-bar`, created once with `xcrun notarytool store-credentials agent-sounds-bar --apple-id <id> --team-id PN2FR53G7Y` (needs an app-specific password; the user runs it). All three are overridable with `SIGN_IDENTITY`, `TEAM_ID`, `NOTARY_PROFILE`.

## Update architecture (`Updates.swift`, `UpdateCard.swift`)
Modeled on CodexBar's path for Homebrew and unsigned installs (CodexBar uses Sparkle only for signed direct downloads).
- `UpdateChecker` (singleton in `AppEnvironment`) reads `GET api.github.com/repos/ealexisaraujo/agent-sounds-bar/releases?per_page=30` unauthenticated. First check 8 s after launch, then whenever 24 h have passed (an hourly timer checks the age). Background failures stay silent; manual ones show in the banner.
- `UpdateChannel`: `stable` (non-prerelease only) or `beta` (also prereleases). Stored in UserDefaults `updateChannel`; the default is beta only when the running version is itself a prerelease. Automatic checks: `automaticUpdateChecks` (default on).
- `Release.newest(in:channel:newerThan:)` is the pure selection (drafts ignored, SemVer precedence in `AppVersion`). Tested in `UpdatesTests`.
- `InstallSource.detect`: Homebrew when the app runs from `/Applications` or `~/Applications` and `<prefix>/Caskroom/agent-sounds-bar` exists for `/opt/homebrew` or `/usr/local`; otherwise direct.
- Applying: Homebrew + stable release runs `brew update --quiet` then `brew upgrade --cask ealexisaraujo/tap/agent-sounds-bar` in the background, then relaunches via `/bin/sh -c 'sleep 1; open <bundle>'` and terminates. Everything else (direct install, or a beta on a Homebrew install) opens the release zip in the browser.
- UI: `UpdateCard` above the popover footer (available, installing, failed, and up-to-date/checking only after a manual check); `UpdateMenuItems` in the gear menu (check/update, channel picker, auto toggle, version line); an Updates section in the configuration window's Overview tab.
- CLI: `AgentSoundsBar version`, `AgentSoundsBar check-update [--beta]` (exit 0 up to date, 10 update available, 1 failure).

## How to extend
- Self-install for direct downloads (download, verify the Developer ID team of the new bundle, swap, relaunch), or Sparkle with an appcast, if direct installs become common.
- Signing and notarizing in GitHub Actions: export the Developer ID cert as a p12 secret plus a notarytool API key; `release.sh` already takes everything from env vars.
- A beta cask (`agent-sounds-bar@beta`) if Homebrew users want betas in place.
